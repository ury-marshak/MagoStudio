## Availability and startup

- `src/platform/modelProviders.ts`, `providerPreferences.ts`, and `renderTarget.ts` resolve renderer model availability. The cloud route incorporates Mago account state. The existing location flags also affect submission and asset handling. Keep external provider availability separate from those flags.
- `desktop/shared/textModelRoute.ts` retains signed-out legacy routing behavior. Desktop external text selection is separate and must surface configured-provider failures without silently switching to Mago or ComfyUI.
- Director fal actions bypass local model readiness checks. General editor forms, omitted capabilities, and background captions still need a full readiness/fallback audit.
- Director external actions have provider-specific availability and cost labels. Legacy sign-in, credit recovery, and ComfyUI setup UI still exist outside the supported subset; audit those paths before claiming complete independence.
- Account-free startup, editing, and the supported Director workflow passed packaged checks. Startup/background requests and main-process plus renderer network traffic still need a complete audit. Prior log inspection alone does not prove independence.

## Contracts and persisted jobs

The main-process vision boundary takes assembled prompts, ordered encoded images, and generation parameters, retaining local media preparation and response parsing. Director casting and shot composition propagate cancellation; remaining text/vision callers and richer provider identity still need auditing.

The supported Director set includes configurable OpenAI-compatible text/vision, Nano Banana 2/2.1 and MiniMax H3 Image reference generation/editing, fal storyboards, and H3 Max image-reference shots. ## Try the initial text and vision adapter on macOS

1. In Keychain Access, create a password item in the login keychain. Set the item name to `MagoStudio.ExternalProvider`, the account to a name such as `openrouter`, and the password to the API key. Grant access if macOS prompts when Mago first reads the item.
2. Open **Local settings → Providers**. For text, vision, or both, enter the API base URL, an exact model ID from the provider's catalog, and the Keychain account name. Use the same account in both entries to share a key. For OpenRouter, you can set **Reasoning effort** independently for text and vision. Choose **Provider default** to omit the effort setting.
3. Save each entry, then use **Check connection** to look up its model. OpenRouter also checks the saved key and, for vision, image input support. The check makes no generation request.

You can also edit `external-providers.json` alongside the app-level `settings.json`, typically in `~/Library/Application Support/Mago Studio/` for the packaged app. Use the profile directory of the instance you are running and keep API keys in Keychain.

```json
{
  "text": {
    "baseUrl": "https://openrouter.ai/api/v1",
    "model": "openai/gpt-6.1-terra",
    "reasoningEffort": "low",
    "keychainAccount": "openrouter"
  },
  "vision": {
    "baseUrl": "https://openrouter.ai/api/v1",
    "model": "openai/gpt-6.1-terra",
    "reasoningEffort": "low",
    "keychainAccount": "openrouter"
  }
}
```

Vision covers desktop descriptions, captions, AutoPrompt, and shot evaluation. Text covers desktop script chat, image prompt enhancement, the local branch of video prompt optimization, and casting and shot prompt composition for locally managed Director projects. Cancelling a plan aborts its active external text request. A failed external shot prompt pauses the plan before video submission. Desktop prompt optimization displays the external route and uses local asset IDs for video prompt optimization. Local Director chat and casting can pass the text access check without a Mago sign-in or ComfyUI text model. The first-launch choice can be skipped when valid external-provider settings are already present. A fresh profile with valid provider settings opened the local editor in the packaged Apple Silicon app. Live prompt enhancement and image captioning passed with GPT-6.1 Terra at Low reasoning effort. The existing route serves each omitted capability. Errors from a configured capability are surfaced on that path without switching providers.

The adapter expects an HTTPS API with non-streaming Chat Completions and `max_completion_tokens`. Vision requests send up to four inline PNGs. The vision readiness check lists models and, on OpenRouter, checks image input support and the saved key. These checks make no generation requests. Model-specific output limits and quality still need live validation. [OpenRouter Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request) · [OpenRouter vision guide](https://openrouter.ai/blog/tutorials/send-image-to-llm/) · [OpenRouter key check](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-key)

## Configure the fal Keychain account on macOS

Create a password item in the login keychain named `MagoStudio.ExternalProvider`. Use an account such as `fal` and put the fal API key in the password field. Open **Local settings → Providers → fal.ai**, enter the account name, and save. The equivalent file entry is `"fal": { "keychainAccount": "fal" }` in `external-providers.json`.

**Check Keychain** confirms that Mago can read the saved password item without generating. Live authorization and Director rendering have passed the development/packaged checks recorded in the integration plan. Removing the provider in Mago removes its account reference from the settings file. The password item can be managed separately in Keychain Access.

H3 Max is the closest fit to the existing shot composer. The composer already has a `minimax_h3_max` engine tag format with `Image N` and `Video N` labels. Use that format and ensure the image list matches the final numbered prompt. The public schema accepts up to 12 references across modalities, documents a separate `image_url` opening frame, and accepts video references from 2 to 15 seconds each with a 15-second combined cap. The implemented Director path supports image-reference shots with configurable resolution and aspect, defaulting to 768P and 16:9. Select 480P for future authorized video tests. The image-reference field is capped at nine by the current schema, separately from the combined twelve-reference description. It preserves the measured output dimensions and duration. Validate opening-frame and video continuity separately before enabling those paths. ### Generation controls verified against schemas, 2026-11-13

Read the current input schemas for all seven generation/edit routes through fal's read-only model-schema API. The Director controls now expose this supported subset:

| Model | Controls sent by the adapter | Fixed Director behavior |
| --- | --- | --- |
| Nano Banana 2 | 0.5K/1K/2K/4K, supported aspect presets or reference layout, minimal/high thinking, optional seed | One PNG; ordered references; no search |
| Nano Banana 2.1 | 1K/2K/4K, supported aspect presets or reference layout, minimal/medium/high thinking, optional seed | One PNG; ordered references; no search |
| H3 Image (generate/edit) | Approximately 1/2/4/8/16 MP and supported aspect presets or reference layout; converted to aligned `image_size` dimensions | One PNG; generation prompt expansion off; edit has no expansion parameter |
| H3 Max reference-to-video | 480P/768P/1080P, six explicit aspect presets, disabled/balanced/quality prompt expansion, optional seed, existing 5–15 s scene duration | 24 fps and generated soundtrack; no audio switch or frame-rate input on this route; 1080P is latent refinement of 768P |

The image preset ratios range from 9:16 through 21:9 and square/portrait/photo formats. Extreme Nano ratios and adaptive video sizing are not exposed in this first control set. H3 Image remains within the schema's 655,360–20,000,000-pixel area and 1:3–3:1 aspect limits. The current H3 Max `reference_image_urls` field has `maxItems: 9`, despite its description's combined twelve-file limit; Director now caps image-only shots at nine.

Settings are kept per model. Action overrides take precedence over the toolbar choice, explicitly saved project defaults, app defaults in Local settings → Providers, and built-in defaults. Project generation defaults are saved only with the dedicated button. Changing the project canvas does not change an accepted provider job. The main process validates settings before planning, including dry runs; plans snapshot effective settings, fingerprints include them, and jobs retain their exact endpoint payload. Render versions record requested provider parameters separately from measured media sizes/duration. Recovery uses the saved job without reapplying current defaults. Seed “Random” explicitly clears an inherited seed.

Batch actions use toolbar settings; individual references, drafts/edits, storyboard scenes, and shots can override them. Individual dry runs share the normal project invalidation keys. Cost labels use usage-based billing when settings make the old fixed 1K image estimate unreliable. Automated request verification uses mocks. The November 14 no-cost packaged inspection checked Providers, Assets/draft, Storyboard and Scenes, fixed minimum-width toolbar clipping, and verified choices/persistence/overrides; the existing-reference edit form still needs a populated-fixture layout pass. A separately authorized live five-second **480P** shot then verified the saved payload, normal cut attachment, playback/export and reopening. Output measured 832×480/24 fps; combined calculated video/text usage was $0.26152925 under the fresh $1 budget. That scope is complete.
