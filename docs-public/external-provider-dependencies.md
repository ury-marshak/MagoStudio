## Availability and startup

- `src/platform/modelProviders.ts`, `providerPreferences.ts`, and `renderTarget.ts` resolve renderer model availability. The cloud route incorporates Mago account state. The existing location flags also affect submission and asset handling. Keep external provider availability separate from those flags.
- `desktop/shared/textModelRoute.ts` retains signed-out legacy routing behavior. Desktop external text selection is separate and must surface configured-provider failures without silently switching to Mago or ComfyUI.
- Director fal actions bypass local model readiness checks. With any external-provider metadata entry present, omitted text/vision capabilities now fail explicitly; legacy Comfy rendering, model probes, launch/setup and downloads are gated in the main process. General editor UI availability, broader renderer traffic and in-flight configuration changes remain audit gaps.
- Director external actions have provider-specific availability and cost labels. Legacy sign-in, credit recovery, and ComfyUI setup UI still exist outside the supported subset; audit those paths before claiming complete independence.
- Account-free startup, editing, and the supported Director workflow passed packaged checks. Startup/background requests and main-process plus renderer network traffic still need a complete audit. Prior log inspection alone does not prove independence.

### Account-free supported-route trace and validation boundary

1. Isolated provider metadata → `resolveProviderStartupMode(null, settings)` → offline/local identity → no Clerk/backend provider, maintenance poll, Product Fruits, cloud watcher or sync effect. Explicit saved cloud mode is intentionally different.
2. Script/chat/cast/compose → local prompt assembly → configured text HTTPS transport. Reference descriptions/metrics/captions → configured vision transport, or explicit unavailability when omitted; never resolve an omission to legacy inference.
3. Director references/storyboards → selected fal model; shots → durable prepared request → saved typed uploads/submission → immutable job polling/output ingestion → local Timeline/export. Preserve all audited session and uncertain-submission guards.
4. Startup still creates the legacy image-render service, but its injected gate pauses reconciliation/polling before DB writes, endpoint access or network. Historical Comfy endpoints saved in requests cannot bypass this check.

Policy: any text, vision or fal entry in `external-providers.json` disables audited **legacy inference/setup entry points**, including a saved `local-comfy` shot preference. Missing/empty metadata preserves legacy behavior; removing every external entry restores it. Invalid entries never grant fallback permission. This is metadata-only, independent of credentials and Mago identity. Separately, renderer backend/direct tracking and the audited main cloud/upload/mirror/cache/storage/protocol boundaries require a deliberately selected cloud account. Main permission comes from persisted `settings.json` mode, not renderer claims, presigned URLs or historical project origin. Uncached historical Mago storage requires cloud mode; local cached outputs and metadata remain usable without it. Snapshot writes preserve remote URLs without localization when account-free. No per-URL historical-media grant was introduced. The scoped renderer audit now guards raw media/auth/maintenance dispatch and optional SDK/embed entry points independently of the earlier mounts. The account-free bundled HTTPS handler refuses non-bundle forwarding and serves local-only CSP headers. Cloud/unchosen TLS and development paths keep their earlier policy. These checks are not a global firewall or proof of Chromium/package-wide egress containment; already-issued work and library ownership remain separate gaps.
